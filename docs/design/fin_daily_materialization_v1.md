# 财务因子日频化方案（v1）

> 现状：`factor_value_daily` 里 118 个预计算因子共 1,162 万行，但**不是日频面板**——
> 每个交易日只有约 68 只股票有值，每只股票只有约 32 个日期有值。
> 结果是「横截面研究做不了、回测读不全」。本文给出日频化的三条路径与推荐方案。

## 1. 问题实证

| 检查 | 结果 |
|---|---|
| `quality.roe_ttm` 覆盖股票 | 5,460 只 |
| 该因子总行数 | ≈ 176,000 |
| 单日行数（2021-06-30） | **68 行** |
| 单股日期数 | **≈ 32 个**（对应 32 个报告披露日） |

推算：`176,000 / 5,460 ≈ 32 日/股`，`176,000 / 2,600 ≈ 68 股/日`。

**这不是 bug**：财务数据按"报告披露日"写入，天然稀疏。问题在于下游需要日频。

## 2. 什么叫"日频化"

把稀疏点变成**每个交易日每个股票都有值**的形态，规则是 PIT asof：

```
某股在 T 日的因子值 = 该股在 T 日之前（含）最近一次披露的值
```

关键约束：**只能用已公告的**（按 `ann_date`，不是 `end_date`），否则是未来函数。

## 3. 三条路径对比

| 方案 | 做法 | 行数 | 研究可用 | 回测可用 | 成本 |
|---|---|---:|---|---|---|
| **A. 查询时 asof** | 读稀疏表 + pandas ffill | 0（不新增） | ✅ | ⚠️ 慢 | 低 |
| **B. 长表日频** | 逐日展开写入 `factor_value_daily` | **8.7 亿** | ✅ | ✅ | 极高 |
| **C. 宽表日频** | 一行一只股票一天，列=因子 | **1,500 万** | ✅ | ✅ | 中 |

行数估算（5,876 只 × 2,600 天）：B = ×57 因子 = 8.7 亿；C = ×1 行 = 1,500 万。

**结论：B 不可行（8.7 亿行，写入与存储都撑不住），推荐 A + C 两层。**

## 4. 推荐架构：两层

### 第一层：查询时 asof（研究用，零存储）

在 `research/eval/data.py::_attach_extras` 增加 asof 连接：

```python
# 伪代码
rows = query(
    "select code, ts, value from factor_value_daily "
    f"where factor_id='{fid}' and ts <= '{end}'"
)
# 按 code 分组后按 ts 排序，向交易日历 reindex + ffill
```

| 优点 | 缺点 |
|---|---|
| 不新增存储 | 每次报告多 10–20 秒 |
| 天然正确（PIT） | 57 个因子 = 57 次查询 |

**适用**：因子评估、报告、探索性研究。

### 第二层：宽表日频（回测/生产用）

新建 `fin_daily_wide` 表：

```
ts (TIMESTAMP, 分区键)
code (SYMBOL)
<57 个因子列，DOUBLE>
```

| 项 | 值 |
|---|---|
| 行数 | 5,876 × 2,600 ≈ **1,530 万** |
| 列数 | 1 + 1 + 57 = 59 |
| 分区 | 按年（`PARTITION BY YEAR`） |
| 去重键 | `DEDUP UPSERT KEYS(ts, code)` |

**一次构建，回测直接读**——避免每次回测都做 57 次 asof 查询。

## 5. 写入路径：必须用 ILP

现在的 REST 批量插入（500 行/次）在处理 1,500 万行时要 **3 万次请求**，不可行。

| 方式 | 吞吐 | 适用 |
|---|---|---|
| REST `/exec` INSERT | ~2 千行/秒 | 小批量、补丁 |
| **ILP（InfluxDB Line Protocol）** | ~50 万行/秒 | 大批量 ✅ |

项目里已有 ILP 通道（`questdb_client`），构建脚本应走 ILP。

## 6. 正确性规则（最容易错的地方）

| 规则 | 说明 | 检查方法 |
|---|---|---|
| **asof 用 ann_date** | 不是 `end_date`（报告期） | 抽 3 只股票，对比公告日前后 |
| **重述处理** | 同一报告期多次披露，取最新版本，但**生效日 = 版本公告日** | 找有重述的案例 |
| **停牌日** | 停牌期间仍需填充（因子值不变） | 抽停牌股 |
| **上市前** | 不填充（NaN 到上市日） | 检查新上市股 |
| **退市后** | 不填充 | 检查退市股 |

## 7. 验证清单

| 检查 | 及格线 |
|---|---|
| 行数 | 宽表 ≈ 1,530 万 ± 5% |
| 每日覆盖 | 每个交易日 ≥ 4,000 只 |
| 单股连续性 | 抽 10 只，值与稀疏表 asof 完全一致 |
| 前视检查 | 因子值的"生效日"与 `ann_date` 完全一致 |
| 与旧口径对账 | 抽查 5 个因子 × 3 个日期，数值相等 |

## 8. 分阶段实施

| 阶段 | 内容 | 产物 | 工时 |
|---|---|---|---|
| **P1** | `_attach_extras` 支持 asof | 研究报告可直接用财务因子 | 半天 |
| **P2** | 构建脚本（读稀疏表 → 展开 → ILP 写入宽表） | `fin_daily_wide` 1,530 万行 | 1 天 |
| **P3** | `stored_factor_panel` 增加宽表读取路径 | 回测读速提升 10 倍 | 半天 |
| **P4** | 增量更新（每日新增一天） | 日更任务 | 半天 |

**P1 优先**——它不需要新表，就能让财务因子进入研究流程。

## 9. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 宽表列数固定，新增因子要改表 | 灵活性下降 | 每年评估一次列清单 |
| 重述处理错误 | 前视偏差 | 用版本表 `factor_value_announce`（已有） |
| ILP 写入失败无事务 | 部分行丢失 | 按年分区写，写完校验行数 |
| 存储增长 | 磁盘 | 宽表压缩率高，1,530 万行约 1–2 GB |

## 10. 与 AI 模块的关系

日频化完成后，财务因子（57 个）才能真正进入特征矩阵。

否则 AI 模块只能用价量因子——**而价量因子的相关性普遍 0.7 以上**，特征维度实际只有 3–5 个，模型没有发挥空间。
