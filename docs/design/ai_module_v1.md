# AI 模块设计（v1，先文档后实施）

> 目标：把机器学习纳入现有研究体系，**不另起一套评估**。
> 原则：模型产出的分数**就是一个因子**，走同一套五维评分与回补链路。

## 1. 定位与边界

| 做 | 不做 |
|---|---|
| 用多因子构造预测分数 | 不自己实现回测/评估（复用 `research.report`） |
| 走 walk-forward 训练与预测 | 不做样本内调参、不做全样本训练 |
| 把预测结果写入 `factor_value_daily` | 不直接下单、不接交易系统 |
| 记录模型版本、特征清单、超参 | 不隐藏随机性（seed / hash 必须落盘） |

**一句话**：AI 模块是"因子生成器"，产出的东西必须能被现有评估体系检验。

## 2. 架构

```
research/ai/
├── dataset.py      # 面板 → 样本矩阵（X, y, mask），唯一的数据入口
├── features.py     # 因子 → 横截面分位矩阵（复用 price_factor_panel / flow_factor_panel）
├── walkforward.py  # 滚动训练/预测调度，产出 OOS 分数
├── models/
│   ├── ridge.py    # 线性基线（先做这个）
│   ├── gbdt.py     # 树模型（P3 再做）
│   └── base.py     # fit / predict 接口
├── registry.py     # 模型登记：id、版本、特征、超参、训练区间
└── evaluate.py     # OOS IC / 传导比 / 分年稳定性（复用 metrics）
```

数据流：

```
panel ──features──> X(dates × stocks × k)
      ──label────> y(dates × stocks)
              │
        walkforward（按年滚动）
              │
        pred(dates × stocks) ──写入 factor_value_daily──> 走 factor_report
```

## 3. 关键设计决策

### 3.1 预测分数 = 因子

模型输出统一写成因子 `ml.<model_id>_<version>`，例如 `ml.ridge_v1`。

好处：

- 复用 `factor_value_daily`（STORED 因子）；
- 复用五维评分、分层 IC、稳健性、中性化对照；
- 与手工因子**同台比较**，不会出现"模型自带一套漂亮指标"的自欺。

### 3.2 标签：横截面分位

```
y = rank_pct(fwd_20d)      # 不是原始收益
```

理由：消除市场整体涨跌的影响，让模型只学"谁比谁好"。

### 3.3 样本单位

| 选择 | 说明 |
|---|---|
| 每 20 个交易日一个观测 | 与持有期一致，避免重叠 |
| 特征做横截面分位 | 与因子评估口径一致 |
| 训练集 = 全部历史观测 | 只增不减（expanding window） |

**独立样本量约 95 期**——这是硬约束，所有模型复杂度都要按这个来限。

### 3.4 Walk-forward

```
2021 预测：训练 2019–2020
2022 预测：训练 2019–2021
...
```

禁止：随机切分、全样本标准化、用测试年做特征选择。

### 3.5 特征白名单

只用**已通过评估**的因子（五维评分 ≥ C 或 IC > 0.02），且：

| 约束 | 阈值 |
|---|---|
| 特征数 | ≤ 8（Ridge）/ ≤ 15（GBDT） |
| 两两相关 | < 0.8（超了先聚类选代表） |
| 覆盖率 | > 80%（否则填充噪声） |

## 4. 评估协议

| 指标 | 及格线 |
|---|---|
| OOS IC 均值 | > 0.02 |
| OOS IC 胜率（正的比例） | > 55% |
| OOS 逐年 IC | ≥ 70% 年份为正 |
| 与最佳单因子对比 | 合成 IC > 单因子最高 IC |
| 传导比 | > 0.5 |
| 与手工合成（等权）对比 | 必须打平或更好，否则不用模型 |

**最重要的是最后一条**：如果 Ridge 打不过"5 个因子等权"，说明加权方式不重要——这是最常见的结局，要诚实接受。

## 5. 防泄漏清单（实施时逐条检查）

| 风险 | 检查 |
|---|---|
| 标签泄漏 | 特征只用到 T 日及之前的数据 |
| 标准化泄漏 | 均值/标准差只用训练段 |
| 特征选择泄漏 | 因子白名单在训练段确定 |
| 多次试验 | 记录总试验次数，最终阈值按 Bonferroni 收紧 |
| 幸存者偏差 | 用 PIT 成分池（`index_weight`） |
| 未来函数 | 财报类因子按 `ann_date` 对齐 |

## 6. 分阶段实施

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P0（已完成）** | `ridge_experiment.py`：Ridge vs 等权，年度 walk-forward | 出 OOS IC 对比表 |
| **P1** | `dataset.py` + `features.py`：把实验代码模块化 | 同一实验可由 10 行调用完成 |
| **P2** | `registry.py` + 预测落盘为 STORED 因子 | `ml.ridge_v1` 能出完整报告 |
| **P3** | GBDT（15 特征上限） | OOS 表现必须超过 Ridge 才算成功 |
| **P4** | 监控：OOS IC 衰减告警、模型重训计划 | 报告里出现"模型漂移"指标 |

## 7. 风险与备选

| 风险 | 应对 |
|---|---|
| 模型 OOS 全面劣于等权 | 放弃 ML 路线，回到因子挖掘 |
| 特征相关性过高 | 先聚类选代表，再进模型 |
| 样本量不足 | 只用线性模型，不上树/网络 |
| 过拟合无法察觉 | 强制留出最近一年做最终验证，永不参与任何调参 |

## 8. 与现有体系的关系

| 现有 | AI 模块如何使用 |
|---|---|
| `factors/` 因子库 | 特征来源 |
| `research/report` 评估 | 模型分数的裁判 |
| `factor_value_daily` | 预测结果落盘 |
| `factor_report --batch` | 批量出评级 |
| `backtest/` | 组合回测最终验证 |

**不新增评估逻辑，不新增数据源。**
